## Risultati della review post-implementazione (2026-05-03 sera)

Una review completa ha identificato 3 gap di integrazione, tutti già
corretti in questa sessione:

### Gap #1: `find_pvgis_csv` non usata in `calcola_br.py`

`calcola_br.py` (la pipeline principale) usava `os.listdir(proj_dir)` per
trovare il PVGIS CSV — quindi anche se il layout v4.2 metteva il CSV in
`input/`, non veniva trovato. **Fixato**: import + uso di
`find_pvgis_csv()` con fallback root → `input/`.

### Gap #2: `find_pvgis_csv` non usata in `validazione_br.py`

Stesso pattern legacy. **Fixato** identicamente.

### Gap #3: `solratio_bifacial.py` era dead code

Il modulo era creato ma mai chiamato dalla pipeline. Setting
`bifaciality_factor=0.7` in Excel B26 non avrebbe prodotto alcun output.
**Fixato**: aggiunto in `calcola_br.py` un blocco condizionale:

```python
if _bf > 0:
    from solratio_bifacial import bifacial_yield, add_bifacial_to_excel
    bifacial_data = bifacial_yield(p, br_result)
    add_bifacial_to_excel(wb_out, bifacial_data, p)
```

Con `bifaciality_factor=0` (default), il blocco non viene eseguito →
retrocompat bit-per-bit con v4.1.

### Validazioni aggiunte

In `solratio_excel.py / read_parameters`, errori espliciti su:
- `tau_diff ∈ [0, 1]` (cella B25)
- `tau + tau_diff ≤ 1` (vincolo fisico — somma trasmittanze impossibile > 1)
- `bifaciality_factor ∈ [0, 1]` (cella B26)

### Cross-file consistency

- Frame coord (item 7) verificato: `br_engine.py` e `validazione_br.py`
  applicano la stessa rotazione `phi = radians(axis_azimuth - 180)` e
  la stessa formula `(v*cos_phi, -v*sin_phi)`. Per `axis_azimuth=180°`
  default, output bit-per-bit identico al precedente layout.
- Cache scene (item 4) verificato: chiave include tutti i parametri
  rilevanti incluso `axis_azimuth`. Worker usa `oconv -i` su cache hit,
  fallback a full oconv su miss. Fail-safe robusto.
- BRTDfunc (item 9) verificato: con `tau_diff=0` la mappatura su Radiance
  `trans` produce `tspec=1.0` → identica a v4.1.
- Bifacciale (item 11) verificato: con `bifaciality_factor=0` il blocco
  non viene eseguito → identica a v4.1.
